# guest C 回归套件的**已知失败基线**（机器可读版；叙述与裁决见 KNOWN-FAILURES.md）
#
# 语义：这里列出的用例文件**预期整体 FAIL**。runner（run-guest-tests.sh）据此判定：
#   - 失败集合 ⊆ 本基线            → 退出 0（打印"已知失败"摘要）
#   - 出现基线外的新失败            → 退出 1（回归）
#   - 基线内的用例**变成通过**      → 退出 1（基线过期，必须同步收紧）
# 最后一条是刻意的：docs/testing.md §四 约定"行为修复时测试会变红，强制同步更新"，
# 否则修好的东西会被基线继续掩盖。
#
# 每行格式：`<用例文件名> [@native|@wine]`（不含路径与扩展名）；
# `#` 起始为注释；空行忽略。可选的模式标注让同一份基线适配两种运行环境。
# 用 WBOX_GUEST_NO_BASELINE=1 可关闭基线判定，回到"任一失败即非零"的原始语义。
#
# ============================================================================
# 2026-07-27：引擎从 blink（C）换成 crates/wbox-linux（纯 Rust）后重定基线。
#
# **这是一次真实的 guest ABI 覆盖回退，不是测试环境问题。** 旧引擎除
# t_net_sockopt@wine 外全绿；新引擎当前 5 通过 / 16 失败。之所以仍然合入：
# 全 Rust 化本身是 PRD §2.2.1 的发布验收条件（旧引擎是 122k 行 C），而
# 补齐 ABI 是 §4.9 F4.R3–R6 明确在跟踪的后续工作。基线如实记录现状，
# 任何**新**回归照样会让门禁变红，任何修好的项也会强制回来收紧这份文件。
#
# 缺口分组（逐条根因见 docs/rust-rewrite.md §4）：
#
#   A. MAP_SHARED 映射不跨进程共享，文件映射也不写回宿主
#      t_exec t_fork_mem
#      fork/execve/wait4 本身已实现（快照式，见 syscall/process.rs），
#      这两个用例剩下的失败全部集中在共享映射：稀疏页表在 fork 时按值
#      深拷贝，MAP_SHARED 区域因此在父子之间断开。
#   B. socket 族与 epoll 未实现
#      t_net_epoll t_net_sockopt t_negative
#      （t_negative 剩下的失败是 socket 与 rlimit 边界校验）
#   C. eventfd / timerfd / signalfd 未实现；信号不投递
#      t_eventfd t_timerfd t_signalfd t_signal_timer
#   D. 快照式 fork 的并发语义差异
#      t_proc —— 子进程在 fork 返回前就跑完了，所以 waitpid(WNOHANG) 不可能
#      看到"还在运行"，父子也无法互相发信号。这是取舍而不是 bug，见
#      syscall/process.rs 顶部的说明。
#   E. mount(2) 未实现（hostfs / MS_RDONLY 挂载）
#      t_mount_ro
#   F. 文件描述（file description）级共享状态未建模
#      t_fd_open t_fd_rw —— dup 出来的 fd 应共享 O_APPEND/O_NONBLOCK 等
#      状态标志与文件偏移；当前 dup 走宿主 try_clone，状态标志各自一份。
#      另含管道容量与非阻塞写的边界。
#   G. mmap 的部分精度（私有文件映射的 mremap 增长回读）
#      t_mmap
#   H. 宿主 symlink 不防护（rootfs 内指向外部的符号链接可被顺出去）
#      t_sec_path t_sec_linkabs
#
# H 组是唯一带安全含义的一组，**范围已收窄**：越根路径（`/..`、`../../..`、
# 绝对宿主路径）现在一律拒绝，`t_sec_path_abshost` 与 `t_sec_path_relesc`
# 已全通并留在基线之外（回归会立刻变红）。剩下的是 symlink 链，与旧引擎
# 同样的限制。
# ============================================================================

# A. MAP_SHARED
t_exec
t_fork_mem

# B. socket / epoll
t_net_epoll
t_net_sockopt

# C. eventfd / timerfd / signalfd / 信号投递
t_eventfd
t_timerfd
t_signalfd
t_signal_timer

# D. 快照式 fork 的并发语义差异
t_proc

# E. mount(2)
t_mount_ro

# F. file description 级共享状态
t_fd_open
t_fd_rw

# G. mmap 精度
t_mmap

# B'（同 socket 组）：rlimit/socket 边界校验
t_negative

# H. 宿主 symlink 不防护（越根路径已修，见上）
t_sec_path
# 只在 Linux 宿主失败：Windows 上建 symlink 需要特权，逃逸链根本搭不起来，
# 该用例反而通过。标注 @linux 才能让同一份基线在两个宿主上都成立。
t_sec_linkabs @linux

# I. Windows 宿主的 stat / symlink 能力差异（不是引擎回归）
# st_nlink 在 Windows 侧是合成值（拿不到真实硬链接数），且建 symlink 需要
# 特权，symlink 环路（ELOOP）测不起来。Linux 宿主上本用例通过，故标 @windows。
t_path @windows
